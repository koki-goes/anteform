# 設計原則

これらは探索を導く原則であり、実装済み機能を示すものではありません。

1. **人の判断を見えるようにする。** 人が決める箇所とシステムが準備したものを明確にする。
2. **コンテキストを確認可能にする。** 情報の出所を示し、不足・古さ・不確実さの可能性を伝える。
3. **不足を表に出す。** 根拠なく答えを作るのではなく、コンテキスト不足を状態として扱う。
4. **人が成果を作れるよう支援する。** 重要な内容や行動への人の制御を保ちながら、理解を意図的な成果へつなぐ。
5. **操作の負担を減らす。** 繰り返し指示しなくても関連する仕事を認識しやすくすることを目指す。
6. **データを最小限にする。** タスクに必要な情報だけを使い、公開資料に非公開データを出さない。
7. **根拠を得てから主張する。** 構想、試作、観察、検証済みの結果を区別する。
